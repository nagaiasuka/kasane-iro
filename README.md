# かさねいろ

半透明の7枚のカードを重ね、お題の色に近づけるスマートフォン向けローカルゲーム。
Expo Managed Workflow / React Native / TypeScript。縦画面・日本語・ローカル完結。

現在のステージは日本の伝統色119問・四季の色40問・自然の色40問・色彩を学ぶ30問の計229問です。
各ステージで3 / 5 / 10問または全問を選択できます。

## 起動

Node.js 22 LTS以上を推奨します。

```sh
npm ci
npm start
```

実機のExpo Goで確認する場合は `npx expo start --go` を実行し、
同じWi-Fi上のスマートフォンでQRコードを読み込みます。SDK 55対応のExpo Goが必要です。
ブラウザーでの補助確認には `npm run web` を使用できます。

iOSシミュレーターに正式アイコン付きの独立したアプリをインストールする場合は
`npm run ios` を実行してください（macOS / Xcodeが必要）。
Releaseビルドを作るため、初回はCocoaPodsなどの準備に時間がかかります。
インストール後は開発サーバーなしでホーム画面の「かさねいろ」から起動できます。
コードや画像を変更した場合は再度 `npm run ios` でビルドしてください。
Expo Goをシミュレーターで開く場合は `npm run ios:go` を使用します。

`ios/` と `android/` はExpo Prebuildの生成物としてGit管理から除外しています。
ネイティブ設定は `app.json` とプラグインで管理してください。
React Native 0.83のローカル依存ファイルURLの不具合に対応するため、
`postinstall` で日本語パスをURLエンコードする限定的な修正を適用します。
依存更新時は `scripts/fix-ios-unicode-path.cjs` の必要性を再確認してください。
開発クライアントを使う場合は `npx expo run:ios` でビルド・起動できます。
AndroidはAndroid StudioのDevice Managerで端末を起動し、
`npm run android` でサーバー不要のRelease APKをビルド・インストールします。
Android SDKとJDK 17以上が必要です。SDKを検出できない場合は
`ANDROID_HOME` をSDKの場所（macOS標準では `$HOME/Library/Android/sdk`）に設定してください。
Expo Goでの確認には `npm run android:go` を使用してください。
ローカルのRelease APKは動作確認用の署名です。ストア提出にはEASのproductionビルドを使用してください。

## 操作

- 手札のカードを中央へドラッグ。カードの中心が点線内に入ると追加されます。
- 場では後から置いたカードが上になります。上端を少しずらし、下のカードもつかめます。
- 場のカードを下部の手札エリアへドラッグすると戻ります。再追加すると最上段になります。
- どちらのエリアにも入らない場合やジェスチャー中断時は元の位置へ戻ります。
- 場の中で移動するだけでは順序は変わりません。
- リセットですべて手札に戻ります。回答するとその時点の配列・生成色・再現率をメモリー内に保存します。
- 回答すると回答完了画面に進み、「次へ」などのボタンで次のプレイヤー・問題・結果へ進みます。手動回答は1枚以上必要です。時間切れは空回答も保存し、0%になります。

## 色と採点

カードの濃度名をalphaとしては使いません。`cards.ts` のRGBとopacityは仮設定です。
手札・ドラッグ中・場で同じRGBAを使用し、カード本体のopacityは変更しません。
中央のカードが重なった無地部分と「いまの色」は白背景での同じsource-over合成です。
端の線やラベルは装飾で、採点に含めません。

お題は問題マスタの `generatedHex` を表示し、プレイヤーの色は既存の `generateColor` で計算します。
全229問について、正解recipeの合成色とgeneratedHexの一致をテストしています。
正解recipeとカード・順番が完全一致した回答は必ず **100.0%**。
他の配列はRGBユークリッド距離を最大距離で正規化し、表示上の誤認を防ぐため99.9%を上限にしています。
これは物理的な減法混色や正式な伝統色の再現モデルではありません。
実物との校正やLab / Delta Eの導入は、独立したエンジンと採点関数で対応できます。

現在の流れは下記Phase 4を参照してください。Phase 3で設定・複数人進行・採点集計の基盤を追加しました。
「最後にまとめて表示」では各問結果を省略します。1〜4人、3 / 5 / 10問、
15 / 30 / 60秒または無制限に対応。初期値は1人・3問・無制限・各問結果です。
名前の空欄は「プレイヤーN」に戻ります。

追加ファイル:

- `src/screens/TitleScreen.tsx`：タイトル
- `src/screens/GameSettingsScreen.tsx`：ゲーム設定
- `src/screens/PlayerSetupScreen.tsx`：名前入力
- `src/screens/HandoffScreen.tsx`：スマホ受け渡し
- `src/screens/QuestionResultScreen.tsx`：各問結果・共通振り返り表示
- `src/screens/FinalResultScreen.tsx`：平均ランキング・全問振り返り・再プレイ
- `src/components/Screen.tsx`：共通の紙色背景、ボタン、選択肢、入力スタイル
- `src/components/ColorSwatch.tsx`、`PlayerResult.tsx`：色見本・個人結果
- `src/game/session.ts`：純粋なゲーム進行、回答保存、集計、残り秒数
- `tests/session.test.ts`：ゲーム進行の回帰テスト

`src/types/game.ts` にセッション型を追加。`App.tsx` がセッションを保持し、
準備画面はトップレベルstate、ゲーム中は `gameStatus` で画面を切り替えます。
追加ナビゲーションライブラリは使用していません。
回答保存・次プレイヤー・次問題の判定はUIから独立した純粋関数です。Phase 4では回答保存と、その後の進行を分離しました。

回答はプレイヤーID・問題ID・順序付きレシピ・生成色（`color`）・再現率・時間切れフラグを保存。
表示中のプレイヤーと問題の照合、保存済み回答のチェック、画面側のrefロックで二重確定を防ぎます。
回答後は一時状態を消去してプレイ画面をアンマウント。次のプレイ画面は問題とプレイヤーをキーに再生成し、
手札・ドラッグ状態・タイマーを初期化します。受け渡し画面には前回答を表示しません。

タイマーはプレイ画面の開始時刻から期限を設定し、200ms間隔で実時刻との差を再計算します。
受け渡し待機中は進みません。バックグラウンド中も期限は延長せず、復帰時に再確認します。
期限到達時は確定済みのstackを保存します。ドラッグ中の未配置カードは含めません。
空回答は白色・0%。手動確定後はタイマーとAppState購読を解除します。

最終スコアは全問題の未丸め再現率の算術平均。降順に並べ、同点は1位・1位・3位方式です。
浮動小数点誤差のみ許容し、表示は小数1桁に丸めるため、見た目の数値が同じでも順位が異なる場合があります。
再プレイは同じ設定・名前で回答履歴を空にして開始します。タイトルへ戻るとセッションを破棄します。
アプリ再起動やWebリロードで途中経過は失われます。

問題は `selectQuestions` で119問から設定数をランダム抽選します。
同じrecipeまたはgeneratedHexを持つ問題は同一ゲーム内で重複させません。
同じ設定での再プレイでも新しく抽選します。
既存の `ColorCard`、`PlayField`、`colorEngine`、`scoring`、`stack` は変更していません。

## Phase 4：画面の区切りと問題詳細（Phase 4.1でUXを改善）

タイトルから「遊び方」をいつでも開けます。ゲームの流れは以下です。

```text
タイトル → ステージ選択 → ゲーム設定 → プレイヤー名
→ 受け渡し（2〜4人のみ）→ 問題開始 → プレイ → 回答完了
→ 次プレイヤーの受け渡し / 問題結果 / 次問題 / 最終結果
最終結果 → 問題一覧の各行 → 問題詳細 → 最終結果
```

追加した画面:

| ファイル | 役割 |
| --- | --- |
| `src/screens/HowToPlayScreen.tsx` | お題・カード・重ね順・再現率の4ブロックと、複数人の説明 |
| `src/screens/StageSelectScreen.tsx` | 「日本の伝統色」を1つのカードとして選択 |
| `src/screens/QuestionIntroScreen.tsx` | 問題番号・プレイヤー・色名・読み・大きな色見本・開始ボタン |
| `src/screens/AnswerSavedScreen.tsx` | 回答保存の区切りと、進行先に応じたボタン |
| `src/screens/ResultDetailScreen.tsx` | 選択した問題の色・各プレイヤーの結果と最終結果への戻りボタン |

`src/data/stages.ts` に `Stage` 型の配列を置き、`src/components/StageCard.tsx` で表示します。
現在は日本の伝統色のみ。問題IDの配列を `createSession` に渡して問題を選択するため、
将来はステージデータを追加できます。設定画面にも選択したステージ名を表示します。
`GameSettings` と `PlayerAnswer` の形は変更していません。

セッションの変更:

- 初期状態と次問題の開始は、1人なら `questionIntro`、複数人なら `handoff`。
- `ready` は `handoff → questionIntro`、`startQuestion` は `questionIntro → playing`。
- `saveAnswer` は回答を保存し `answerSaved` で停止。プレイヤー・問題のindexはまだ進めません。
- `continueAfterAnswer` はボタン操作で次プレイヤーの `handoff`、`questionResult`、次問題へ分岐。
- `resultTiming: 'final'` は各問結果を省略。最終回答完了のボタンで `finished` になります。
- 各問結果を出す既存値 `'question'` を維持しています（指示書の `each` に相当）。
- 各関数は該当する状態以外では変更せず、重複操作によるスキップや二重回答を防ぎます。

問題開始・回答完了・問題結果は自動では進みません。既存PlayScreenとタイマー処理は変更せず、
「はじめる」でマウントした時点から計時します。問題開始・受け渡し・回答完了にはタイマーがありません。
回答完了画面には回答データ自体を渡さず、作成色・カード・レシピ・再現率・正解を表示しません。

各問結果と問題詳細は同じ表示を再利用し、お題を100pxの見本に拡大して得点順に並べます。
最終結果は1人なら「あなたの平均再現率」、複数人なら同点対応ランキングです。
問題一覧から開く詳細のindexはApp側のUI状態で保持し、セッションと集計は変更しません。
Phase 4.1では問題結果・詳細で正解レシピを表示します。再プレイは同じステージ・設定・名前を使います。
